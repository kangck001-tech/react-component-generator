# create-pr: 템플릿 기반 Pull Request 생성

이 스킬은 **forked 서브 에이전트**에서 실행된다. 메인 대화와 분리된 컨텍스트에서 저장소를 읽고, PR을 만들고, 결과 URL과 요약만 메인으로 돌려준다.

PR 본문 템플릿은 `references/` 아래에 두 벌 있다.

- `references/pr-template.en.md`: 해외 오픈소스 프로젝트용 영문 템플릿
- `references/pr-template.ko.md`: 국내 프로젝트용 한국어 템플릿

## 워크플로우

### Step 0: 저장소와 브랜치 확인

1. `git rev-parse --is-inside-work-tree`로 git 저장소인지 확인한다. 아니면 중단하고 알린다.
2. `gh auth status`로 GitHub 인증을 확인한다. 실패하면 중단하고 `gh auth login` 필요를 알린다.
3. 저장소 루트의 `AGENTS.md`/`CLAUDE.md`에 PR 관련 지침이 있으면 이 스킬의 기본값보다 우선한다.
4. 현재 브랜치가 기본 브랜치(`main` 또는 `master`)면 PR을 만들 수 없다. 사용자에게 새 브랜치 이름을 정해 달라고 요청하지 말고, 변경 내용 기반으로 `feat/...`, `fix/...` 형식의 브랜치를 만들어 옮긴다. 그 사실을 결과에 적는다.

### Step 1: 커밋 상태 확인

1. `git status --short`로 확인한다.
2. **커밋되지 않은 변경이 남아 있으면 PR을 만들지 않고 중단한다.** 이 스킬은 커밋을 대신하지 않는다. "커밋되지 않은 변경이 있습니다. 먼저 commit 스킬로 커밋해 주세요."라고 알린다.
3. 기본 브랜치 대비 커밋이 없으면(`git log <base>..HEAD`가 비어 있으면) 만들 PR이 없다고 알린다.

### Step 2: 기본 브랜치와 변경 파악

1. 기본 브랜치는 `gh repo view --json defaultBranchRef -q .defaultBranchRef.name`으로 확인한다.
2. `git log <base>..HEAD --format=%s%n%b`로 커밋 메시지를, `git diff <base>...HEAD --stat`과 필요한 범위의 `git diff <base>...HEAD`로 실제 변경을 읽는다.
3. 변경 목적을 한두 문장으로 정리한다. 커밋 메시지를 나열하지 말고, 리뷰어가 왜 이 변경이 필요한지 알 수 있게 요약한다.
4. 테스트 명령은 `package.json` 스크립트(`test`, `lint`, `build` 등)에서 찾는다. 이번 세션에서 실제로 돌린 결과가 있으면 그 결과를 쓰고, 돌리지 않았으면 "실행하지 않음"이라고 적는다. 통과했다고 추측해서 쓰지 않는다.

### Step 3: PR 언어 결정

템플릿 언어는 아래 순서로 정한다. 앞 단계에서 결정되면 뒤 단계는 보지 않는다.

1. **사용자 명시**: 요청에 `영문`, `English`, `--lang en`, `한국어`, `--lang ko`가 있으면 그대로 따른다.
2. **저장소의 기존 PR 템플릿**: `.github/PULL_REQUEST_TEMPLATE.md`, `.github/pull_request_template.md`, `docs/` 아래 템플릿이 있으면 그 언어를 따른다. 저장소가 쓰는 템플릿을 무시하면 안 된다.
3. **프로젝트 언어 신호**: 다음을 읽어 한글 비율을 본다.
   - `README.md`, `CONTRIBUTING.md`의 본문
   - 최근 커밋 메시지 20개
   - 한글(`가-힣`)이 전체 글자의 30% 이상이면 한국어, 그 미만이고 영어 문장이 주가 되면 영문이다.
4. **외부 오픈소스 판별**: `git remote get-url origin`의 소유자가 현재 `gh` 계정(`gh api user -q .login`)과 다르고, README와 CONTRIBUTING이 영문이면 영문 템플릿을 쓴다.
5. **판단 불가**: 신호가 엇갈리거나 없으면 PR을 만들지 말고, 메인 에이전트에게 "영문/한국어 중 어떤 템플릿을 쓸지"를 되물어 달라고 결과로 돌려준다.

결정한 언어와 근거(어떤 신호로 골랐는지)는 결과 보고에 반드시 적는다.

### Step 4: PR 본문 작성

1. 결정한 언어의 템플릿을 `references/` 에서 읽는다. 템플릿 구조는 바꾸지 않는다. 섹션을 빼거나 새로 만들지 않는다.
2. 각 섹션을 Step 2의 분석으로 채운다.
   - 해당 없는 항목은 지우지 말고 `N/A`(영문) 또는 `해당 없음`(한국어)으로 적는다.
   - 체크리스트는 실제로 확인한 항목만 `[x]`로 표시한다.
3. 본문 맨 끝에 다음 attribution 줄을 붙인다. 현재 세션의 시스템 지침이 이 줄을 요구하는 경우에만 붙인다.
   `🤖 Generated with [Claude Code](https://claude.com/claude-code)`
4. 본문은 임시 파일(예: 저장소 밖 `$TMPDIR` 또는 `/tmp`)에 쓰고 `--body-file`로 넘긴다. 셸 인자에 여러 줄을 직접 넣지 않는다.

### Step 5: 푸시와 PR 생성

1. 현재 브랜치를 원격에 푸시한다. `git push -u origin HEAD`를 쓰고, `--force`는 쓰지 않는다.
2. PR 제목은 70자 이내로 쓴다. 커밋 컨벤션이 있으면 그 형식을 따르되, 언어는 PR 템플릿 언어와 맞춘다.
   - 영문 템플릿: 영문 제목
   - 한국어 템플릿: 한국어 제목
3. `gh pr create --base <base> --title "<제목>" --body-file <임시파일>`로 생성한다. 초안이 필요하면 `--draft`를 붙인다.
4. 같은 브랜치에 이미 열린 PR이 있으면 새로 만들지 말고 `gh pr view`로 기존 PR을 보고한다.

### Step 6: 결과 보고

메인 에이전트에게 아래 항목을 짧게 돌려준다.

- PR URL
- 선택한 템플릿 언어와 근거
- 브랜치 이름(기본 브랜치에서 옮겼다면 그 사실)
- 실행한 테스트와 결과, 또는 "실행하지 않음"
- 중단했다면 중단 이유와 사용자가 해야 할 일

## 하지 않는 것

- 커밋되지 않은 변경을 자동으로 커밋하지 않는다. 커밋은 `commit` 스킬의 일이다.
- `--force` 푸시, 기본 브랜치 직접 푸시를 하지 않는다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
- 템플릿 구조를 임의로 바꾸지 않는다.
- PR을 머지하거나 리뷰를 승인하지 않는다.
- 언어 판단이 애매한데 임의로 고르지 않는다. 이 경우 결과로 질문을 돌려준다.
